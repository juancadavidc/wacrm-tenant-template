# PNL.1 (PRD wacrm-marca-ui) · Pantalla Configuración → Marca — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** sección **Configuración → Marca** (`?tab=brand`) para owner y superadmin: nombre, logo completo, ícono y color con la fuente de cada uno, vista previa (sidebar, pestaña, login) antes de guardar, errores por campo, aviso de ícono no cuadrado, "Restaurar" por campo, sidebar y favicon que cambian sin recargar, y el aviso en Tu perfil; en español e inglés (y ko/pt por la paridad de `messages/`).

**Architecture:** la lógica de la pantalla vive en un controlador sin React (`crearControladorMarca`) que habla con `/api/marca` (`I1`, CT.1) por un `fetch` inyectado, valida antes de enviar con `validarPut` del contrato y lee cada respuesta con sus esquemas zod; así las pruebas corren en el entorno `node` de vitest contra `crearStubFetchMarca` sin agregar jsdom ni testing-library. La vista (`PanelMarcaVista`) es presentacional y se prueba con `renderToStaticMarkup`, como `profiles-panel.test.tsx`. Al guardar o restaurar, `MarcaProvider` pasa a tener estado y `aplicarMarcaEnDocumento` cambia el `<link rel="icon">` y el `<style id="marca-tokens">` sin recargar.

**Tech Stack:** Next 16.3.8 (App Router, componentes cliente), React 19.2, next-intl 4, zod 4, vitest 5 (entorno `node`), lucide-react.

**Spec:** `prd-hub` → `prds/wacrm-marca-ui/slices/PNL.1-pantalla-marca.md` (origen `03-alcance#panel-marca`, `05-reglas#r5`, `#r6`, `#r8`, `#r9`, `#r11`). Contratos que consume: `slices/CT.1-contrato-api-marca.md` (`contracts/marca/api.ts`, plan `docs/superpowers/plans/2026-11-23-ct.1.md`) y `slices/CT.2-contrato-marca-efectiva.md` (`contracts/marca/marca.ts`, plan `docs/superpowers/plans/2026-11-23-ct.2.md`).

## Decisiones tomadas sin Juan

1. **Pruebas de UI sin jsdom.** El repo prueba la UI con `renderToStaticMarkup` en entorno `node` y no tiene testing-library. Agregarla tocaría `package.json` (archivo caliente). Por eso las interacciones (elegir archivo, guardar, restaurar) se prueban en el controlador puro y la vista se prueba renderizando estados.
2. **Id de sección `brand`** (lo fija el slice: `?tab=brand`), en el grupo `workspace`, ícono `Stamp` de lucide, justo antes de `members`.
3. **Quién la ve:** `puedeEditarMarca({ accountRole, user })` = `permiteEditarMarca(rol)` del contrato, con `rol = 'superadmin'` si `esSuperadmin(user)`, `'owner'` si `accountRole === 'owner'`, `'admin'` si es admin y `'usuario'` en cualquier otro caso (agent, viewer, sin rol). Un perfil de acceso no entra en la cuenta (R5).
4. **`?tab=brand` sin permiso cae a Resumen** (`resolveSection` devuelve `overview`), igual que una pestaña desconocida, y no se pide la API. Mientras `profileLoading` es `true` y la URL pide `brand`, el panel no pinta nada (evita mostrar Resumen un instante a un owner). Además, si la API responde 403, la vista muestra solo "No tienes permiso para editar la marca".
5. **Validación antes de enviar:** al elegir un archivo o al guardar se corre `validarPut` del contrato. Un archivo inválido (p. ej. `.jpg`) deja el motivo junto al campo y **no** cambia el borrador ni la vista previa ("no cambia nada"). Un 400 del servidor se muestra igual, campo por campo.
6. **Aviso de ícono no cuadrado:** se muestra en la vista previa en cuanto se elige el ícono (medido en el navegador con `createImageBitmap`; si no se puede medir, p. ej. algunos SVG, no se avisa antes) y, tras guardar, según `avisos` del `PUT`, que es lo que manda. El ícono se guarda igual (R6).
7. **Un solo botón "Guardar"** envía en un `PUT` todo lo que cambió (nombre, color, logo, ícono). Si nada cambió, el botón queda deshabilitado (evita el 400 `sin-campos`).
8. **"Restaurar" solo aparece en un campo con fuente `base`** (lo único que hay para borrar, R9). Tras el `DELETE`, junto al campo se lee "Volvió a `config/`" o "Volvió a Stackless" según `fuentes[campo]` de la respuesta. Restaurar no pide confirmación (se puede volver a subir).
9. **Cambiar sin recargar:** `MarcaProvider` guarda la marca en estado y expone `useActualizarMarca()`. Con la respuesta del `PUT` o del `DELETE`: `fusionarMarca` actualiza `nombre`, `color`, `logoUrl` y `marcaUrl = iconoUrl` (y `iconoUrl`/`fuentes` si el tipo `Marca` ya los tiene tras MRC.1); `aplicarMarcaEnDocumento` cambia el `href` de cada `<link rel~="icon">` a `iconoUrl` (y crea uno si no hay) y reescribe `#marca-tokens` con el color. El título de la pestaña **no** se cambia en vivo (no lo pide el slice; cambia en la próxima carga).
10. **CSS de los tokens en un solo sitio:** la cadena que hoy arma `src/app/layout.tsx` pasa a `cssDeMarca(color)` en `src/lib/marca/color.ts`, y la usan el layout y `aplicarMarcaEnDocumento`. Choque esperado con MRC.1, que también toca `layout.tsx`: rebase trivial.
11. **El tipo `Marca` del contexto no se cambia aquí** (lo cambia MRC.1 al tipo de `I2`). `fusionarMarca` es genérica sobre `{ nombre; color; logoUrl; marcaUrl }` y copia `iconoUrl`, `fuentes` y `logoPropio` solo si el objeto actual ya tiene esa llave, así funciona antes y después de MRC.1.
12. **Vista previa con URLs locales:** el archivo elegido se muestra con `URL.createObjectURL` (inyectado en el controlador) y se revoca al guardar, al elegir otro o al desmontar.
13. **CDC contra la API real:** las pruebas de la pantalla se escriben una sola vez como `suiteCdcPantalla(crearFetch)` y corren contra el stub de CT.1. La corrida contra la API real (`pantalla.api-real.test.ts`) se escribe real si al implementar `src/app/api/marca/route.ts` (MRC.2) y la `leerMarca()` de MRC.1 ya están en `main`; si no, queda con `it.todo` y su cabecera dice que la cierra quien mergee el último de MRC.1/MRC.2. Para confirmar con Juan.
14. **Textos en ko y pt además de es y en:** la prueba de paridad de `messages/` falla con una llave solo en en/es.
15. **Aviso de Tu perfil para todos los roles;** "Configuración → Marca" es enlace solo para quien puede editar la marca (para los demás es texto en negrita: un enlace los llevaría a Resumen).

### Task 3: Controlador de la pantalla

**Files:**
- Create: `src/components/settings/marca/controlador-marca.ts`
- Test: `src/components/settings/marca/controlador-marca.test.ts`

**Interfaces:**
- Consumes: de `@contracts/marca/api`: `RUTA_API_MARCA`, `validarPut`, `MarcaApiSchema`, `RespuestaPutSchema`, `ErrorValidacionSchema`, `ErrorSimpleSchema`, `MarcaApi`, `Campo`, `Fuente`, `MOTIVOS`; en la prueba, `crearStubFetchMarca`, `CONFIG_STUB`, `MARCA_DEFECTO_STUB` de `@contracts/marca/api.stub`.
- Produces:
  - `type MotivoCampo = 'vacio' | 'muy-largo' | 'formato' | 'tipo' | 'muy-pesado'`
  - `type EstadoPanel = { fase: 'cargando' | 'lista' | 'sin-permiso' | 'error-carga'; actual: MarcaApi | null; borrador: { nombre?: string; color?: string; logo?: File; icono?: File }; previas: { logoUrl?: string; iconoUrl?: string }; errores: Partial<Record<Campo, MotivoCampo>>; iconoNoCuadrado: boolean; guardando: boolean; restaurado: { campo: Campo; fuente: Fuente } | null; errorGeneral: 'red' | 'cuerpo-muy-pesado' | 'sin-permiso' | null }`
  - `type DepsControlador = { fetch: (input: string, init?: RequestInit) => Promise<Response>; crearUrl: (f: File) => string; revocarUrl: (u: string) => void; medir: (f: File) => Promise<{ ancho: number; alto: number } | null>; alAplicar: (m: MarcaApi) => void }`
  - `crearControladorMarca(d: DepsControlador): { estado(): EstadoPanel; suscribir(fn: () => void): () => void; cargar(): Promise<void>; cambiarTexto(campo: 'nombre' | 'color', valor: string): void; elegirArchivo(campo: 'logo' | 'icono', f: File): Promise<void>; guardar(): Promise<void>; restaurar(campo: Campo): Promise<void>; vistaPrevia(): { nombre: string; color: string; logoUrl: string; iconoUrl: string }; hayCambios(): boolean; desmontar(): void }`
- Comportamiento:
  - `cargar`: `GET` → 200 `fase 'lista'` con `actual`; 403 → `'sin-permiso'`; otro status o error de red → `'error-carga'`.
  - `cambiarTexto`: guarda en `borrador` y borra el error de ese campo. El color se valida al guardar.
  - `elegirArchivo`: `validarPut({ [campo]: f })`; con error → `errores[campo]` y nada más cambia. Válido → `borrador[campo] = f`, revoca la URL previa de ese campo, `previas` con `crearUrl(f)`; si es ícono, `iconoNoCuadrado = medida !== null && ancho !== alto`.
  - `vistaPrevia`: `borrador`/`previas` sobre `actual.marca`; sin ícono propio (ni en borrador ni en `actual`) el ícono de la vista previa es el logo de la vista previa (R2).
  - `guardar`: `validarPut(borrador)` falla → `errores`, sin `fetch`. Si no, `PUT` con `FormData` (solo lo que está en `borrador`); 200 → `actual` = respuesta sin `avisos`, `iconoNoCuadrado` según `avisos`, borrador y previas vacíos (URLs revocadas), `alAplicar(respuesta)`; 400 `validacion` → `errores = campos`; 403 → `errorGeneral 'sin-permiso'`; 413 → `'cuerpo-muy-pesado'`; red → `'red'`. Fuera del 200, `alAplicar` no se llama.
